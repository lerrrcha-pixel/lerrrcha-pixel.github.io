# Карта компетенций: какие задачи решает выпускник курса «Аналитик SOC»

## Как карта описывает результат курса

Карта описывает, что умеет выпускник курса «Аналитик SOC» после обучения. Каждая строка отвечает на четыре вопроса: какую задачу выпускник решает, по каким действиям это видно, каким заданием курс это проверяет и на какие данные исследования опирается решение.

Строка карты состоит из пяти полей.

1. Компетенция. Профессиональная задача, которую выпускник решает на работе.
2. Индикаторы. Два или три действия, которые эксперт видит со стороны. У каждого действия есть условие и критерий качества.
3. Доказательство. Задание, которое проверяет индикаторы.
4. Уровень на выходе. Степень самостоятельности, которой выпускник достигает к концу курса.
5. Основание. Данные исследования, на которые опирается компетенция.

Карта различает три уровня самостоятельности.

1. По инструкции. Аналитик решает задачу на типовых случаях по плейбуку, а старший аналитик проверяет решение.
2. Самостоятельно. Аналитик решает задачу на типовых и части нетиповых случаев без контроля и объясняет своё решение.
3. Развивает. Аналитик улучшает процесс: пишет правила и плейбуки, обучает коллег.

Курс выпускает аналитика первой линии, который умеет решать часть задач второй линии. Основную работу первой линии выпускник выполняет самостоятельно, а задачи второй линии по инструкции. Третий уровень в курс не входит: аналитик достигает его на работе, когда вырастает до второй линии.

## Какие термины встречаются в карте

| Термин | Что означает |
|---|---|
| SOC | Центр мониторинга и реагирования на инциденты информационной безопасности. Аналитики SOC круглосуточно следят за событиями в инфраструктуре компании и реагируют на атаки |
| L1, L2, L3 | Линии SOC. Первая линия разбирает оповещения и реагирует на типовые инциденты, вторая расследует сложные инциденты, третья ищет скрытые атаки и наставляет младших коллег |
| Оповещение | Сообщение системы защиты о подозрительном событии, которое аналитик должен разобрать |
| Ложное срабатывание | Оповещение, за которым нет атаки. Например, SIEM принимает ночное резервное копирование за выгрузку данных |
| SIEM | Система, которая собирает журналы событий со всех серверов и программ компании и находит в них подозрительное по правилам корреляции |
| Правило корреляции | Условие, по которому SIEM находит атаку в потоке событий. Например, «больше 20 неудачных входов в одну учётную запись за пять минут» |
| EDR | Программа на каждом компьютере и сервере, которая записывает действия процессов и по команде аналитика отключает хост от сети |
| IDS | Система обнаружения вторжений, которая находит признаки атак в сетевом трафике |
| IRP | Система учёта инцидентов, в которой аналитик заполняет карточку инцидента и записывает свои действия |
| SOAR | Система, которая автоматически выполняет шаги реагирования: проверяет адрес по базам угроз, блокирует учётную запись |
| Плейбук | Пошаговая инструкция, по которой аналитик реагирует на инцидент одного типа |
| Эскалация | Передача инцидента на следующую линию SOC вместе со всеми фактами, которые собрал аналитик |
| SLA | Срок, за который аналитик должен взять оповещение в работу по договорённости с заказчиком |
| Индикатор компрометации | Признак атаки в данных: адрес сервера злоумышленника, домен, хеш вредоносного файла |
| MITRE ATT&CK | Каталог тактик и техник злоумышленников с открытым доступом. Тактика называет цель этапа атаки, техника называет конкретный способ |
| Kill Chain | Модель, которая делит атаку на последовательные этапы: от разведки до достижения цели |
| Sysmon, auditd | Программы, которые записывают подробные журналы событий в Windows и в Linux |
| КИИ | Критическая информационная инфраструктура: информационные системы в здравоохранении, энергетике, транспорте, финансах и других отраслях из перечня 187-ФЗ |
| ГосСОПКА, НКЦКИ | Государственная система обнаружения компьютерных атак и её координационный центр, который принимает уведомления об инцидентах на объектах КИИ |

## Какие знания курс проверяет на входе

Курс рассчитан на ИТ-специалистов, поэтому базовые ИТ-знания входят во входные требования. Слушатель проходит входной тест, а при пробелах проходит бонусный модуль из библиотеки компании.

| Знание | Что проверяет входной тест | Что получает слушатель, если тест показал пробел |
|---|---|---|
| Администрирование Windows и Active Directory | Учётные записи, группы, групповые политики, службы | Бонусный модуль по Windows и Active Directory |
| Работа в Linux | Командная строка, права доступа, процессы, журналы systemd | Бонусный модуль по Linux |
| Сети | TCP/IP, модель OSI, DNS, DHCP, NAT, VPN, прокси | Бонусный модуль по сетям |
| Скрипты | Основы Python или Bash: переменные, циклы, чтение файла | Бонусный модуль по Python |

Работодатели упоминают Windows в 72% вакансий L1, Linux в 67%, сети в 50%. Школы, которые учат ИТ-специалистов, тоже выносят базу во входной тест: Яндекс Практикум, INSECA, CyberED.

## 1. Как аналитик разбирает очередь оповещений и отсеивает ложные срабатывания

Разбор очереди оповещений составляет основную работу первой линии. Аналитик решает, какое оповещение взять первым, и отделяет атаки от ложных срабатываний.

| № | Компетенция | Индикаторы | Доказательство | Уровень | Основание |
|---|---|---|---|---|---|
| 1.1 | Разбирает очередь оповещений от самых критичных к менее критичным | 1. Берёт критичное оповещение в работу не позже чем через пять минут, остальные не позже чем через 15 минут.<br>2. Повышает или понижает приоритет оповещения с учётом бизнес-контекста: роли пользователя, назначения хоста и времени события.<br>3. Обрабатывает в срок SLA не меньше 90% оповещений смены. | Учебная смена в тренажёре: очередь из 30 оповещений за два часа. Тренажёр записывает время, когда аналитик взял оповещение в работу, и итоговый приоритет. | 2. Самостоятельно | Работодатели называют мониторинг в 89% вакансий L1. Anti-Malware приводит сроки в пять и 15 минут как пример SLA. Авторы статей пишут, что новички часто оценивают критичность без учёта бизнес-контекста. В программах 16 курсов-конкурентов нет работы с очередью и SLA. |
| 1.2 | Отделяет ложные срабатывания от инцидентов | 1. Собирает контекст оповещения за 15 минут: пользователя, хост, процесс и историю похожих событий за 90 дней.<br>2. Сначала ищет признаки легитимного действия, потом признаки атаки, и проверяет вывод по первоисточнику события.<br>3. Выносит вердикт «ложное срабатывание» или «инцидент» и подтверждает его минимум двумя признаками. Не меньше 80% вердиктов верны. | Очередь из 20 оповещений, среди которых четыре настоящих инцидента. Аналитик выносит вердикт по каждому оповещению, эксперт сверяет вердикты с эталоном. | 2. Самостоятельно | По данным статей, 60–80% оповещений в SOC ложные. Авторы статей пишут, что новички часто закрывают оповещение по шаблону и не проверяют первоисточник события. Автор статьи «Reverse Duck Test» на Хабре описывает порядок «сначала доказать легитимность». |
| 1.3 | Готовит исключение для ложного срабатывания, которое повторяется | 1. Формулирует условие исключения так, чтобы оно не скрывало атаку той же техники.<br>2. Оформляет заявку на исключение: какое правило сработало, почему срабатывание ложное, сколько раз оно повторялось. | Аналитик готовит заявки на исключение по трём ложным срабатываниям, которые повторяются. Эксперт проверяет, не пропустит ли исключение атаку из набора учебных данных. | 1. По инструкции. Исключение утверждает старший аналитик | Авторы статей называют заявку на исключение обязательным шагом работы с ложными срабатываниями. Работодатели называют правила корреляции в 33% вакансий L1. |

## 2. Как аналитик находит следы атаки в журналах и телеметрии

Системный администратор знает Windows и Linux, но обычно не знает журналы событий безопасности. Курс учит читать журналы глазами защитника: какие события выдают атаку и как по ним восстановить действия злоумышленника.

| № | Компетенция | Индикаторы | Доказательство | Уровень | Основание |
|---|---|---|---|---|---|
| 2.1 | Восстанавливает действия на хосте Windows по журналам событий | 1. По событиям входа, запуска процессов и изменения групп, например 4624, 4625, 4688 и 4728, и журналу Sysmon строит хронологию действий на хосте за период из задания.<br>2. Определяет тип входа: интерактивный, сетевой, служебный или через удалённый рабочий стол, то есть RDP.<br>3. Находит признаки подбора пароля, входа под чужой учётной записью и повышения прав в Active Directory. | Журналы хоста Windows, на котором побывал злоумышленник. Аналитик строит хронологию атаки и указывает событие, которое подтверждает каждый шаг. | 2. Самостоятельно | Работодатели называют Windows в 72% вакансий L1, Active Directory в 26% вакансий аналитиков SOC. Журналы Windows, Sysmon и Active Directory входят в программы всех курсов-конкурентов для ИТ-специалистов. |
| 2.2 | Восстанавливает действия на хосте Linux по журналам событий | 1. По журналам аутентификации, journald и auditd строит хронологию действий пользователя.<br>2. Находит признаки подбора пароля по SSH, повышения прав через sudo и закрепления через задачи cron.<br>3. Работает с журналами российских дистрибутивов Astra Linux и ALT Linux. | Журналы сервера Linux, на котором побывал злоумышленник. Аналитик восстанавливает действия злоумышленника и указывает события, которые их подтверждают. | 2. Самостоятельно | Работодатели называют Linux в 67% вакансий L1, российские ОС в 8% вакансий аналитиков SOC. Авторы статей относят российские ОС к специфике работы SOC в России. |
| 2.3 | Находит признаки атаки в сетевых журналах | 1. По журналам межсетевого экрана, прокси и DNS находит сканирование портов, соединения с сервером, через который злоумышленник управляет атакой, и выгрузку данных.<br>2. Разбирает оповещение IDS: какое правило сработало, на какой трафик и подтверждают ли его другие источники. | Набор сетевых журналов за сутки и пять оповещений IDS. Аналитик отделяет атаки от легитимного трафика. | 2. Самостоятельно | Работодатели называют сети в 50% вакансий L1, межсетевые экраны в 39%, IDS в 28%. |
| 2.4 | Использует данные EDR при разборе оповещения | 1. По дереву процессов, сетевым соединениям и изменениям файлов и реестра определяет, что запустилось на хосте и откуда.<br>2. Изолирует хост от сети через EDR, когда плейбук разрешает этот шаг первой линии. | Три оповещения EDR в тренажёре. Аналитик описывает цепочку процессов и решает, изолировать ли хост. | 2. Самостоятельно | Работодатели называют EDR в 28% вакансий L1 и в 59% вакансий L2 и L3. Эксперты BI.ZONE называют понимание EDR обязательным до первой смены. |

## 3. Как аналитик ищет события и пишет правила в SIEM

Работодатели называют SIEM в 89% вакансий L1, поэтому работа в SIEM составляет основу навыков аналитика. Курс учит работать в российской SIEM и в системе с открытым исходным кодом, чтобы навык переносился между продуктами.

| № | Компетенция | Индикаторы | Доказательство | Уровень | Основание |
|---|---|---|---|---|---|
| 3.1 | Ищет события в SIEM с помощью запросов | 1. Составляет запрос на языке SIEM с фильтрами по полям, времени и логическими условиями.<br>2. Строит выборку и агрегацию: самые активные хосты, число событий по часам, процессы, которые запускались только на одном или двух хостах.<br>3. Выполняет один и тот же поиск в российской SIEM и в ELK. | 10 поисковых задач в двух SIEM с ограничением по времени. | 2. Самостоятельно | Конкретный продукт работодатели называют только в 8–15% вакансий аналитиков SOC: KUMA в 15%, MaxPatrol SIEM в 14%, ELK в 12%. Массовые курсы учат только на ELK и Wazuh. |
| 3.2 | Пишет правило корреляции по описанию техники атаки | 1. По описанию техники из MITRE ATT&CK пишет правило корреляции в одной SIEM.<br>2. Проверяет правило на учебных данных: правило срабатывает на атаку и не срабатывает на легитимные действия из набора.<br>3. Описывает правило: что оно ищет, по каким источникам событий работает, какие ложные срабатывания у него известны. | Аналитик пишет два правила по техникам из задания. Эксперт запускает правила на наборе данных с атаками и легитимной активностью. | 1. По инструкции | Работодатели называют правила корреляции в 33% вакансий L1 и в 70% вакансий L2 и L3. Правила корреляции относятся к задачам L2, поэтому кандидат на позицию L1 с этим навыком выделяется среди других соискателей. |

## 4. Как аналитик реагирует на инцидент и передаёт его следующей линии

Аналитик первой линии останавливает типовую атаку по плейбуку и вовремя передаёт сложный инцидент второй линии. Когда аналитик ошибается с эскалацией, опасный инцидент остаётся без внимания специалиста.

| № | Компетенция | Индикаторы | Доказательство | Уровень | Основание |
|---|---|---|---|---|---|
| 4.1 | Реагирует на типовой инцидент по плейбуку | 1. Выбирает плейбук по типу инцидента: фишинг, подбор пароля, заражение вредоносной программой, выгрузка данных.<br>2. Выполняет шаги сдерживания, которые плейбук разрешает первой линии: блокирует учётную запись, изолирует хост, блокирует адрес.<br>3. Записывает каждое действие в IRP с временем и результатом. | Четыре инцидента разных типов в тренажёре. Эксперт сверяет действия аналитика с чек-листом плейбука. | 2. Самостоятельно | Работодатели называют реагирование на инциденты в 100% вакансий L1, плейбуки в 33%, IRP и SOAR в 44%. |
| 4.2 | Передаёт инцидент на следующую линию | 1. Решает по критериям плейбука, передавать ли инцидент на L2.<br>2. Заполняет карточку эскалации: что произошло, когда, какие активы пострадали, какие индикаторы аналитик нашёл и какие действия уже выполнил.<br>3. Аналитик L2 продолжает работу по карточке и не задаёт вопросов аналитику первой линии. | Пять инцидентов в тренажёре, два из них требуют эскалации. Эксперт в роли аналитика L2 оценивает карточки. | 2. Самостоятельно | Работодатели называют эскалацию в 39% вакансий L1. Авторы статей пишут, что новички часто неверно эскалируют инциденты и важное остаётся на первой линии. |
| 4.3 | Разбирает фишинговое письмо | 1. По заголовкам письма определяет настоящего отправителя и путь письма.<br>2. Проверяет ссылки и вложения по базам угроз и в песочнице.<br>3. Находит в почтовой системе других получателей того же письма. | Три письма, одно из которых легитимное. Аналитик выносит вердикт по каждому письму и описывает, как проверял. | 2. Самостоятельно | Авторы статей называют фишинг с вредоносным вложением типовым инцидентом первой линии. Работодатели называют песочницы в 17% вакансий L1. |

## 5. Как аналитик восстанавливает цепочку атаки

Расследование относится к задачам второй линии, но элементы расследования отличают сильного кандидата на позицию L1. Выпускник выполняет их по инструкции. Исключение составляет MITRE ATT&CK: аналитики всех линий описывают атаки в терминах этого каталога, поэтому выпускник работает с ним самостоятельно.

| № | Компетенция | Индикаторы | Доказательство | Уровень | Основание |
|---|---|---|---|---|---|
| 5.1 | Относит действия злоумышленника к тактикам и техникам MITRE ATT&CK | 1. Определяет тактику и технику по событию или цепочке событий.<br>2. По найденной технике предполагает следующие шаги злоумышленника и проверяет их в SIEM. | 10 событий из разных этапов атаки. Аналитик относит каждое событие к технике и обосновывает выбор. | 2. Самостоятельно | Работодатели называют MITRE ATT&CK в 17% вакансий L1 и в 62% вакансий L2 и L3. |
| 5.2 | Восстанавливает цепочку атаки по нескольким источникам | 1. Связывает оповещения разных источников и разных смен в один инцидент.<br>2. Строит хронологию атаки по этапам Kill Chain: от первичного доступа до последнего действия злоумышленника.<br>3. Определяет масштаб инцидента: какие хосты и учётные записи пострадали. | Итоговое расследование: многоэтапная атака в учебной инфраструктуре, данные из SIEM, EDR и сетевых журналов. | 1. По инструкции | Работодатели называют расследование в 61% вакансий L1 и в 78% вакансий L2 и L3, Kill Chain в 11% и в 38%. Ищет индикаторы в SIEM за последние 90 дней и сообщает о совпадениях. | Отчёт об угрозе и данные SIEM за 90 дней. Аналитик находит хосты, которые связывались с инфраструктурой злоумышленника. | 1. По инструкции | Работодатели называют индикаторы компрометации в 27% вакансий L2 и L3, в вакансиях L1 их нет. |

## 6. Как аналитик документирует работу и общается с коллегами и заказчиком

Аналитик SOC работает в смене и обслуживает заказчиков, поэтому результат работы он передаёт коллегам и заказчику в виде текста: карточек, отчётов, сводок. Ошибка в тексте приводит к потере информации так же, как ошибка в анализе.

| № | Компетенция | Индикаторы | Доказательство | Уровень | Основание |
|---|---|---|---|---|---|
| 6.1 | Пишет отчёт об инциденте для разных адресатов | 1. Пишет технический отчёт для ИТ-службы: хронологию, индикаторы и рекомендации по устранению.<br>2. Пишет резюме для руководства на одну страницу без технических терминов: что произошло, каков ущерб, какие меры приняла команда, какое решение нужно от руководства. | Два отчёта по итоговому расследованию. Эксперт оценивает их по критериям полноты, точности и понятности для адресата. | 2. Самостоятельно | Работодатели называют отчёты в 22% вакансий L1 и в 46% вакансий L2 и L3. Из курсов-конкурентов отчёты есть в основном у Яндекс Практикума. |
| 6.2 | Передаёт смену | 1. Составляет сводку смены: открытые инциденты, их статус, ответы, которые смена ждёт от заказчика или L2.<br>2. Аналитик следующей смены продолжает работу по сводке без устного уточнения. | Учебная смена заканчивается передачей другому слушателю. Он оценивает, хватило ли сводки, чтобы продолжить работу. | 2. Самостоятельно | Работодатели называют сменный график в 67% вакансий L1. Авторы статей называют потерю информации между сменами слабым местом SOC. В программах 16 курсов-конкурентов передачи смены нет. |
| 6.3 | Уточняет обстоятельства инцидента у пользователя и ИТ-службы | 1. По сценарию уточняет у пользователя, совершал ли он действие из оповещения.<br>2. Формулирует запрос ИТ-службе так, чтобы специалист понял, что нужно сделать и в какой срок. | Ролевая игра в тренажёре: эксперт играет пользователя и ИТ-специалиста заказчика. | 2. Самостоятельно | Работодатели называют работу с заказчиками в 22% вакансий L1 и в 38% вакансий L2 и L3. Эксперты AM Live называют общение с бизнесом обязательным навыком аналитика. |

## 7. Как аналитик автоматизирует рутину и проверяет решения ИИ

SOAR и ИИ-ассистенты уже разбирают часть оповещений без человека. Аналитик первой линии пишет простые скрипты для рутинных шагов и проверяет решения автоматики там, где ошибка обходится дорого.

| № | Компетенция | Индикаторы | Доказательство | Уровень | Основание |
|---|---|---|---|---|---|
| 7.1 | Автоматизирует рутинный шаг разбора скриптом на Python | 1. Пишет скрипт, который проверяет список индикаторов через API базы угроз и сохраняет результат в таблицу.<br>2. Пишет скрипт, который разбирает журнал и выбирает события по условию. | Два скрипта на учебных данных. Скрипт проверяет 100 индикаторов без ручных действий. | 1. По инструкции | Работодатели называют Python в 22% вакансий L1 и в 41% вакансий L2 и L3, автоматизацию в 11% и в 57%. Синтаксис Python входит во входные требования, поэтому курс учит только прикладным задачам аналитика. |
| 7.2 | Проверяет решения ИИ-ассистента и автоматических правил | 1. Перепроверяет по первоисточникам вердикты ИИ-ассистента на выборке оповещений и находит ошибочные.<br>2. Определяет, какие типы оповещений нельзя закрывать автоматически, и обосновывает решение ценой ошибки. | 20 оповещений с вердиктами ИИ-ассистента, среди которых есть ошибочные. Самостоятельно | Представители Positive Technologies заявляют, что их система закрывает 68% инцидентов без аналитика. 75% участников опроса AM Live опасаются, что автоматика по ошибке заблокирует бизнес-сервисы. ## 8. Как аналитик работает с регуляторами и выходит на рынок труда

Аналитик SOC в госсекторе и на объектах КИИ взаимодействует с ГосСОПКА. Выпускнику курса также нужно пройти техническое собеседование, а до технического этапа доходит примерно один кандидат из 10.

| № | Компетенция | Индикаторы | Доказательство | Уровень | Основание |
|---|---|---|---|---|---|
| 8.1 | Готовит сведения для уведомления НКЦКИ об инциденте на объекте КИИ | 1. Определяет по списку активов заказчика, затронул ли инцидент объект КИИ.<br>2. Собирает сведения для уведомления по форме НКЦКИ и передаёт их ответственному сотруднику в установленный срок. | Кейс с инцидентом на объекте КИИ. Аналитик заполняет уведомление по форме. | 1. По инструкции | Работодатели называют ГосСОПКА и КИИ в 5–7% вакансий аналитиков SOC. Ни одна из изученных SOC-программ не разбирает взаимодействие с ГосСОПКА. Авторы статей называют указ 250 и 187-ФЗ источниками спроса на SOC. |
| 8.2 | Проходит техническое собеседование на позицию L1 | 1. Разбирает кейс вслух: какие данные смотрит, какие гипотезы проверяет, на чём основан вывод.<br>2.
